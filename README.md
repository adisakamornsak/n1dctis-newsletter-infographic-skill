# PEA Newsletter Infographic

**Plugin / Skill v3.0.0 — ไม่ต้องติดตั้งโปรแกรมในเครื่องผู้ใช้**

จัดทำ Newsletter ภาษาไทยตาม CI ม่วง–ทองของ PEA มีแนวทางจัดหน้า 5 แบบ ชื่อแผนกกำหนดได้ ใช้ภาพข่าวที่จำเป็นครบทุกภาพ และส่งงานเป็น JPG/JPEG แนวตั้ง 1440×2560 เพียงภาพเดียว ใช้คำสั่งและทรัพยากรจาก **เวอร์ชันล่าสุดที่ระบบ Plugin ซิงก์แล้ว** ไม่ตรวจ GitHub หรืออัปเดตในเครื่องก่อนทุกคำขอ

## เริ่มใช้บนเว็บ เดสก์ท็อป และมือถือ

1. ติดตั้ง/เปิดใช้ PEA Newsletter Infographic จาก Plugin ที่ผู้ดูแลเผยแพร่ให้บัญชีหรือ Workspace ของคุณ
2. เลือก Plugin/สกิลในแชท แนบข่าวและภาพทั้งหมด แล้วระบุชื่อแผนกหากต้องการเปลี่ยนค่าเริ่มต้น
3. ผู้ช่วยตรวจความสามารถของเครื่องมือในแชท อ่านกฎและภาพอ้างอิง แล้วจัดทำและตรวจงานตามข้อกำหนด

ตัวอย่าง: “สร้าง Newsletter จากข่าวและภาพที่แนบ ใช้ sub_header: แผนกบริการลูกค้า และพื้นหลังที่เหมาะกับข่าว”

หากไม่ระบุ `sub_header` หรือเว้นว่าง จะใช้ **แผนกระบบสารสนเทศและความปลอดภัยไซเบอร์** หัวด้านบนและท้ายภาพยังคงข้อความเดิม ผู้ใช้ไม่ต้องมี Git, terminal, Node.js หรือตัวติดตั้งในเครื่อง

Plugin นี้บรรจุคำสั่งและภาพอ้างอิง ไม่ได้ติดตั้งเครื่องมือสร้าง/จัดวางภาพ ฟอนต์ หรือบริการส่งออกเพิ่ม การผลิตงานจริงขึ้นกับเครื่องมือและสิทธิ์ของแชทนั้น หากเข้าถึงภาพต้นฉบับ ตรวจฟอนต์ หรือส่งออก JPG ตามข้อกำหนดไม่ได้ ผู้ช่วยต้องแจ้งข้อจำกัดและไม่อ้างว่าเป็นงานสมบูรณ์ ยังไม่ได้ทดสอบการผลิตภาพบนมือถือจริง

อ่าน [คู่มือติดตั้งและอัปเดตภาษาไทย](docs/install-update.th.md), [คู่มือแพ็กและเผยแพร่](docs/publish-to-github.th.md) และ [การใช้กับเครื่องมืออื่น](docs/usage-with-other-tools.th.md)

## พร้อมนำเข้าเป็น Plugin

- โฟลเดอร์ Plugin ที่บรรจุครบในตัว: [`plugins/pea-newsletter-infographic/`](plugins/pea-newsletter-infographic/)
- Portable manifest: [`plugin.json`](plugins/pea-newsletter-infographic/plugin.json) ตาม Agent Plugins 1.0.0
- Marketplace สำหรับนำเข้าจาก GitHub: [`.agents/plugins/marketplace.json`](.agents/plugins/marketplace.json)
- ต้นฉบับสกิลที่ดูแลแก้ไข: [`pea-newsletter-infographic/`](pea-newsletter-infographic/)

โฟลเดอร์ Plugin เป็นสำเนาที่สร้างจากต้นฉบับเพื่อให้มีโครงสร้าง `skills/<skill-name>/` ครบในแพ็ก ไม่ต้องใช้ symlink หรืออ่านไฟล์นอกแพ็ก อย่าแก้สำเนาโดยตรง ทั้งสองชุดตรวจเทียบข้อมูลทุกไฟล์ได้ และ Git เก็บเนื้อหาไฟล์ภาพที่เหมือนกันเป็น blob เดียว

การมี manifest ยังไม่ใช่การเผยแพร่ Plugin ไปยังบัญชีผู้ใช้ ต้องนำการเปลี่ยนแปลงขึ้น GitHub แล้วนำเข้าใน Workspace หรือทำขั้นตอนเผยแพร่ในระบบ Plugin ตามคู่มือ

## กฎสำคัญ

- ใช้โลโก้ต้นฉบับมุมซ้ายบน ย่ออย่างรักษาสัดส่วนได้ ห้ามวาดใหม่ ตัดขอบ บิด หรือเปลี่ยนสี
- ใช้ภาพข่าวครบทุกภาพ จัด collage/bento grid และ crop-to-fill ได้โดยคงบุคคล ข้อความ และบริบทที่จำเป็น ห้ามสร้างภาพข่าวใหม่ทดแทน
- พื้นหลังเปลี่ยนตามเนื้อหาข่าว ไม่มีการบังคับใช้ดอยสุเทพหรือสถานที่จากภาพอ้างอิง
- Google Sans ที่รองรับไทยเป็นตัวเลือกแรก; หากใช้ไม่ได้ให้ใช้ Google Prompt ที่รองรับไทยและแจ้งฟอนต์สำรอง หากยืนยันฟอนต์ไม่ได้ต้องแจ้งข้อจำกัด ไม่มีไฟล์ฟอนต์ในชุด
- ใช้ Watt-D จากต้นฉบับหรือ cutout ที่อนุมัติเท่านั้น ไม่สร้างตัวละครทดแทน
- ไม่เปลี่ยนตัวเลข วันที่ ชื่อเฉพาะ และข้อเท็จจริง ไม่แต่ง motto/slogan เว้นแต่ผู้ใช้สั่งโดยตรง
- ส่งภาพเดียวเป็น RGB JPG/JPEG 1440×2560 แนวตั้ง ไม่แบ่งหน้า ไม่ละภาพเพื่อแก้ความแน่น และตรวจไฟล์จริงก่อนอ้างว่าสมบูรณ์

## สำหรับผู้ดูแล repo เท่านั้น

ผู้ดูแลใช้ Node.js 20 ขึ้นไปเพื่อสร้างและตรวจแพ็ก ไม่ต้องติดตั้ง dependency เพิ่ม และผู้ใช้ Plugin ไม่ต้องรันคำสั่งเหล่านี้:

```bash
npm run build:plugin
npm test
npm run check:plugin
```

แก้ต้นฉบับสกิลหรือภาพแล้วต้อง build สำเนา Plugin ใหม่ เพิ่มเวอร์ชันใน `plugin.manifest.json`, `package.json`, `SKILL.md` และพรอมป์ต์ทั้งสองชุดให้ตรงกันก่อนเผยแพร่ ไม่มีการ push, publish หรืออัปโหลดภาพข่าวอัตโนมัติ
