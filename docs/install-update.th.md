# ติดตั้งและอัปเดตสกิลจาก GitHub

ใช้ GitHub สาขา `main` เป็นแหล่งเวอร์ชันล่าสุด ไม่ต้องส่งหรืออัปโหลด ZIP
ตัวติดตั้งดาวน์โหลดทั้งสกิล รวมโลโก้ ภาพอ้างอิง และมาสคอตจาก repository เดียวกัน
ไม่ส่งภาพข่าวหรือข้อมูลของผู้ใช้ขึ้น GitHub และไม่ติดตั้งฟอนต์

## สิ่งที่ต้องมี

- Git และ Python 3.10 ขึ้นไป
- อินเทอร์เน็ตที่เข้าถึง GitHub ได้ทุกครั้งก่อนเริ่มงาน
- Codex ที่รองรับสกิลในเครื่อง; คำสั่ง `run` ต้องมี Codex CLI และลงชื่อเข้าใช้แล้ว
- Google Sans ที่รองรับภาษาไทย หรือ Google Prompt เป็นฟอนต์สำรองตามกฎสกิล ต้องจัดหาเอง

คำสั่งตัวอย่างใช้ `python3` บน macOS/Linux หากใช้ Windows ให้ใช้ `py -3` แทน
ตัวอัปเดตใช้ไลบรารีมาตรฐาน Python และ Git ไม่ต้องติดตั้ง Pillow เพื่ออัปเดต
(Pillow ยังจำเป็นเมื่อต้องใช้ตัวช่วยตรวจ/ส่งออกภาพ)

## ติดตั้งครั้งแรก

เปิด Terminal ในโฟลเดอร์ที่ต้องการเก็บ repository แล้วรัน:

```bash
git clone https://github.com/adisakamornsak/n1dctis-newsletter-infographic-skill.git
cd n1dctis-newsletter-infographic-skill
python3 tools/manage_skill.py install
```

ถ้า clone ไว้แล้ว ให้เข้าโฟลเดอร์นั้นแล้วใช้ `git pull --ff-only` ก่อนรันตัวติดตั้ง
สคริปต์ติดตั้งสกิลจาก `main` บน GitHub ไม่ได้นำไฟล์ที่ยังไม่เผยแพร่ในเครื่องเจ้าของมาแจก
ต้องเผยแพร่การเปลี่ยนแปลงชุดนี้ไปยัง `main` ก่อนให้ผู้อื่นใช้คำสั่งติดตั้ง

ถ้ามีสกิลติดตั้งด้วย ZIP หรือวิธีอื่นอยู่แล้ว ให้ใช้:

```bash
python3 tools/manage_skill.py install --replace-existing
```

ตัวเลือกนี้อนุญาตให้สำรองสกิลเดิมทั้งโฟลเดอร์ก่อนแทนที่ ไม่มีการเขียนทับไฟล์เดิมโดยไม่สำรอง
สกิลที่เป็น symlink ต้องจัดการลิงก์เดิมก่อน เครื่องมือจะไม่แก้ปลายทางลิงก์เอง

ตำแหน่งปกติ:

- สกิลใหม่: `~/.agents/skills/pea-newsletter-infographic/`
- หากพบสกิลเดิมใน `$CODEX_HOME/skills/` หรือ `~/.codex/skills/` จะอัปเดตที่เดิม
- ถ้าพบทั้งสองตำแหน่ง จะหยุดให้จัดการสำเนาซ้ำหรือระบุ `--skills-dir` ให้ชัด
- ตัวอัปเดตที่เก็บไว้ใช้งานต่อ: `~/.local/share/pea-newsletter/manage_skill.py`
- Git cache และข้อมูลการอัปเดต: `~/.local/share/pea-newsletter/`
- สำเนาสำรอง: `pea-newsletter-backups/` ข้างโฟลเดอร์ `skills` ไม่วางไว้ภายในโฟลเดอร์ที่ Codex สแกนสกิล

หลังติดตั้ง เก็บ repository ไว้ใช้อัปเดตตัวติดตั้งในอนาคตได้ แต่ตัวอัปเดตที่ติดตั้งไว้ทำงานได้เอง

## เริ่มใช้งานพร้อมตรวจอัปเดตทุกครั้ง — Codex CLI

ให้ใช้คำสั่งนี้เป็นทางเข้าหลักสำหรับการเริ่มงานข่าว:

```bash
python3 ~/.local/share/pea-newsletter/manage_skill.py run --prompt "สร้างข่าวจากข้อมูลที่ฉันจะให้ โดยใช้ sub_header ตามที่ระบุ"
```

แนบภาพได้ไม่จำกัดจำนวนโดยใส่ `--image` ซ้ำ:

```bash
python3 ~/.local/share/pea-newsletter/manage_skill.py run \
  --prompt "สร้างข่าวกิจกรรมจากรายละเอียดต่อไปนี้ ..." \
  --image "/path/to/photo-1.jpg" \
  --image "/path/to/photo-2.jpg"
```

สำหรับ Windows PowerShell ใช้:

```powershell
py -3 "$HOME/.local/share/pea-newsletter/manage_skill.py" run --prompt "สร้างข่าวจากข้อมูลที่ฉันจะให้"
```

ทุกครั้งที่เรียก `run` เครื่องมือจะ:

1. ติดต่อ GitHub และดึง `main` ใหม่ ไม่มีช่วงเวลาข้ามการตรวจหรือใช้ cache แทนเมื่อเครือข่ายล้มเหลว
2. ตรวจไฟล์บังคับ โครงสร้าง เวอร์ชัน และกฎการแพ็กก่อนเปลี่ยนสกิล
3. ตรวจว่าผู้ใช้ไม่ได้แก้ไฟล์สกิลในเครื่อง สำรองฉบับเดิมเมื่อมีการเปลี่ยนแปลง และติดตั้งฉบับใหม่
4. แสดงเวอร์ชันและ commit ที่ตรวจได้ แล้วเปิด **แชท Codex CLI ใหม่** พร้อมเรียก `$pea-newsletter-infographic`

ถ้าอัปเดตหรือยืนยันฉบับล่าสุดไม่สำเร็จ จะคืนสถานะผิดพลาดและไม่เปิด Codex ต่อ
เวอร์ชันล่าสุดหมายถึง commit ของ `main` ที่ GitHub ส่งกลับ ณ เวลาตรวจ ไม่ใช่การเฝ้าดูการเปลี่ยนแปลงระหว่างผลิตข่าว
คำสั่ง `run` เปิด Codex CLI ไม่ได้ควบคุมแชท Desktop ที่เปิดค้างอยู่

## ใช้งานใน Codex Desktop หรือเรียกสกิลตรง ๆ

สกิลรุ่นนี้กำหนดให้ผู้ช่วยรัน `scripts/preflight_update.py` **ก่อนผลิตข่าวทุกคำขอ**
เมื่ออัปเดตสำเร็จ ต้องอ่าน `SKILL.md` และกฎอ้างอิงจากตำแหน่งติดตั้งใหม่ก่อนทำงานต่อ
ตรวจเพียงหนึ่งครั้งต่อคำขอ; การอ่านคำสั่งใหม่ภายในคำขอเดียวกันไม่ต้องวนตรวจซ้ำ

ตัวอย่างสั่งผู้ช่วย:

> ใช้ $pea-newsletter-infographic ทำข่าวนี้ ก่อนเริ่มให้รัน preflight_update.py จากโฟลเดอร์สกิลที่ติดตั้ง และอ่านกฎใหม่หลังอัปเดตสำเร็จ

ขั้นตอนนี้เป็นกฎที่ผู้ช่วยต้องปฏิบัติตาม **ไม่ใช่ hook ที่แอปบังคับในระดับระบบ**
ตัวบังคับที่ทำงานก่อนเปิดแชทโดยตรงคือคำสั่ง `run` ข้างต้น
สกิลเดิมที่ยังไม่ได้ติดตั้งรุ่นนี้จะไม่มีขั้นตอน preflight ต้องติดตั้งใหม่ก่อน
หากแอปไม่เห็นสกิลใหม่ ให้เปิดแชทใหม่หรือเริ่มแอปใหม่

ผู้ใช้ที่นำไปอ่านเป็นข้อความบนระบบซึ่งเรียกคำสั่งในเครื่องไม่ได้ จะตรวจอัปเดตด้วยกลไกนี้ไม่ได้
ระบบนั้นต้องมีขั้นตอนดึง GitHub ก่อนใช้งานแยกต่างหาก และห้ามอ้างว่าได้รัน preflight แล้ว

## อัปเดตอย่างเดียว / ดูสถานะ

```bash
python3 ~/.local/share/pea-newsletter/manage_skill.py update
python3 ~/.local/share/pea-newsletter/manage_skill.py status
```

`status` แสดงข้อมูลในเครื่องเท่านั้น ไม่ติดต่อ GitHub และใช้แทน preflight ไม่ได้
`update` อ่าน `main` ใหม่ทุกครั้ง แม้เลขเวอร์ชันจะเท่าเดิมแต่ commit หรือไฟล์เปลี่ยนก็รับการเปลี่ยนแปลง
สคริปต์ไม่อัปเดตโค้ดตัวติดตั้งเองจาก remote โดยอัตโนมัติ หากมีการแก้ตัวติดตั้ง ให้ `git pull --ff-only` แล้วรัน `install` จาก repository อีกครั้ง

## เมื่อพบปัญหา

- **ไม่มีอินเทอร์เน็ต / GitHub เข้าไม่ได้:** หยุดงาน เชื่อมต่อใหม่แล้วลองอีกครั้ง ไม่ใช้ฉบับเก่าเงียบ ๆ
- **ไฟล์ในเครื่องถูกแก้:** เครื่องมือจะรักษาไฟล์เดิมและหยุด ตรวจงานแก้ของตนก่อน ถ้าต้องการกลับมาตาม GitHub ให้รัน `install --replace-existing` จาก repository เพื่อสำรองก่อนแทนที่
- **main ขาดโลโก้หรือไฟล์บังคับ:** ฉบับที่ติดตั้งยังอยู่ เจ้าของ repo ต้องแก้ไฟล์ต้นทางแล้วเผยแพร่ใหม่ เครื่องมือไม่หาโลโก้อื่นมาแทน
- **อัปเดตซ้อนกัน:** รอให้คำสั่งเดิมจบ หากโปรเซสเดิมหยุดผิดปกติจริง ให้ตรวจว่าไม่มีการอัปเดตค้าง แล้วลบโฟลเดอร์ `~/.local/share/pea-newsletter/.update.lock` ก่อนลองใหม่
- **เปลี่ยนไฟล์ใหม่ไม่สำเร็จ:** เครื่องมือพยายามคืนโฟลเดอร์เดิมทันที สำเนาสำรองที่เก็บไว้สามารถใช้กู้คืนด้วยตนเองได้ ไม่ลบ backup ที่มีเวอร์ชันหรือไฟล์ต่างกันอัตโนมัติ
- **ต้องการติดตั้งคนละตำแหน่ง:** ระบุ `--skills-dir` และ `--state-dir` ก่อนคำสั่ง เช่น `python3 tools/manage_skill.py --skills-dir "/my/skills" --state-dir "/my/pea-state" install` และใช้ค่าเดิมเมื่อเรียกตัวอัปเดต

ในกรณีติดตั้งตำแหน่งกำหนดเอง ใช้คำสั่ง `python3 /my/pea-state/manage_skill.py --skills-dir /my/skills --state-dir /my/pea-state run`
Codex ต้องถูกตั้งค่าให้มองเห็นตำแหน่งสกิลนั้นด้วย

## สำหรับเจ้าของ repository

เผยแพร่ไฟล์ที่ตรวจผ่านแล้วไปยัง `main` และคงชื่อโฟลเดอร์ `pea-newsletter-infographic/`
เมื่อผู้ใช้เริ่มงานครั้งถัดไปผ่านตัวเปิดใช้งานหรือ preflight จะรับ commit ใหม่นั้น
ไม่จำเป็นต้องสร้าง ZIP หรือ GitHub Release ทุกครั้ง และไม่ต้องติดตั้งงานตั้งเวลาในเครื่องผู้ใช้
เครื่องมือนี้ไม่มีคำสั่ง push หรือเปลี่ยนการตั้งค่า GitHub

ก่อนเผยแพร่:

```bash
python3 -m unittest discover -s tests -v
python3 tools/package_skill.py --output dist/skill.zip --force
```

การทดสอบตัวติดตั้งใช้ Git repository จำลองในเครื่อง ครอบคลุมการรับ commit ใหม่
การรักษางานแก้ในเครื่อง การสำรอง/คืนไฟล์ การอัปเดตผ่าน preflight และการหยุดก่อนเปิด Codex เมื่อดึงข้อมูลไม่ได้
ไม่ได้เปิดงานผลิตข่าวจริงระหว่างทดสอบ
