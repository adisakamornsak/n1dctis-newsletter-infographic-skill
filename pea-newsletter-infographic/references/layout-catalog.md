# Visual style catalog: five PEA newsletter concepts

This document tells the team how to select a layout. Every variant uses the same protected PEA logo (inserted from `assets/pea-logo-exact-original.png`), the EXACT permanent Thai header and footer, Google Sans-only newly composed typography, uncropped original user photos, purple/gold CI, and untouched source numbers. PEA Watt-D may be added as a supporting mascot when suitable, and the decorative background can change according to story type.

## 01 - Chiang Mai Classic (existing approved concept)

- File: `assets/approved-layout-reference.png`.
- Composition: top hero with Chiang Mai mountains, pagoda, old city wall; title/date at left; main image/content to left, points/steps at right; three photo cards and information box below.
- Use for general PEA activity reports, field inspections and team newsletters with strong documentary imagery.
- Flexible modules: key-points list, field photos, equipment details. Do not create four steps by default.
- Mascot/background note: use PEA Watt-D sparingly near the title or footer if the story is friendly/informal; background can lean to Chiang Mai, community, or light field-work motifs.

## Layout routing / avoiding repeated design

1. Honor explicit style requests (`01`, `02`, `03`, `04`, `05`, or variant name).
2. Without a choice, match the primary subject. For mixed themes, prefer main news intent: activity/field (01), IT service/platform (02), security guidance (03), validated KPIs/business systems (04), technical operations/infrastructure (05).
3. Decide mascot usage separately from the layout. A story may use the same layout with or without PEA Watt-D depending on tone.
4. Choose the decorative background according to the story theme, not only the layout reference. The same layout can have a different backdrop when needed.
5. When a series covers similar stories, rotate between compatible options and change the hero drawing/geometry, mascot placement, or background treatment, without changing brand constants or original attachments. Do not rely on memory of earlier issues unless the user provides them.
6. If the source has a very small amount of text, minimize sections; if too much, reduce decoration, condense without losing meaning, reflow and enlarge the same canvas; do not add pages. Never invent content to match a gallery's shapes.
7. Allow an original appropriate background image or icon set based on content. Pure decorative cyber/digital/friendly visuals may be generated; supplied photos and their pixels may not.

## Common restrictions on ALL five reference images

The provided concept images are NOT production-ready or truth sources: they include generated lettering, fictional photos/control-room scenes, sample dates, steps, statistics and logo approximations. Borrow *layout geometry, color, motif, hierarchy*, not the literal image background or unverified content. Overlay the exact original PEA logo and typeset exact departmental text programmatically in the finished output. Use only user-provided source imagery for real field activities. Even if an image example looks similar to the true PEA logo, replace it with the original asset in an actual document.

## All five layouts: one-canvas adaptation (v2.2.0)

Treat photo counts and aspect ratios in examples as illustrative, not binding. Accept any number of news images with no template-defined cap. All five styles must place every required image into one coherent static PNG. Use a hero plus adaptive gallery for small/medium sets, or modular grids/filmstrips on a taller canvas for larger sets. Keep one brand header and footer, not repeated page panels. Do not copy sample KPI values, infer unseen facts, invent a motto, or reduce screenshots to unreadable decorations. Follow `references/single-image-layout.md` relative to the skill root for manifest and capacity checks.
